# Конфигурация домашнего сервера

Снимок того, что работает на `192.168.101.7` и живёт **вне** этого репозитория:
виртуалхосты nginx, systemd-юниты, compose-файлы сервисов и скрипты хоста.
Собрано 16.08.2026 с работающей машины.

Зачем: код бота лежит в git и переживёт что угодно, а обвязка вокруг него до сих
пор существовала в единственном экземпляре — на самом сервере. Восстанавливать её
по памяти после отказа диска пришлось бы неделю.

## Что внутри

| Каталог | Что там |
|---|---|
| `nginx/` | виртуалхосты: `photo`, `tv`, `sub`, `pult`, дефолтный обработчик и внутренний конфиг зеркала |
| `systemd/` | наши юниты и таймеры: NAT-шлюз, tv-vpn, зеркало подписок, синк Immich↔Jellyfin, продление сертификатов, zapret |
| `compose/` | по файлу на каждый сервис: Immich, Jellyfin, Transmission, AdGuard, Kavita, дашборд, панель VPN и прочие |
| `sbin/` | скрипты хоста из `/usr/local/sbin` и обёртка `zapret-ctl` |
| `homepage/` | конфигурация дашборда |
| `system/` | `fstab`, netplan, udev-правило таймаута для сыплющегося диска, конфиг zapret |

## Чего здесь намеренно нет

`.env` любого сервиса, приватные ключи из `ssh/`, сертификаты Let's Encrypt,
`.htpasswd` зеркала и сами данные сервисов. Всё это либо секреты, либо слишком
велико для git.

⚠️ **API-ключи Jellyfin и Immich в `homepage/services.yaml` заменены на
`ЗАМЕНИТЬ_КЛЮЧОМ`** — при восстановлении подставьте настоящие из панелей
соответствующих сервисов, иначе виджеты дашборда останутся пустыми.

## Как этим пользоваться

Это снимок, а не система развёртывания: файлы копируются на место руками.
Порядок восстановления с нуля описан в [MIGRATION.md](../MIGRATION.md) — там же
перечислены мины, на которых переезд ломается тихо.

Пути внутри файлов завязаны на `/home/san` и пользователя `san`. Данные лежат на
`/mnt/storage` (Seagate 4 ТБ) и `/mnt/pool` (mergerfs из двух старых дисков), в
привычные места они приходят bind-монтированием из `fstab` — см. `system/fstab`.

Снимок стареет: после заметных правок на сервере пересоберите его заново.
