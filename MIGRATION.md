## 5. Мины

### Мина 1 — три каталога `/path/to`

Плейсхолдеры из примеров compose, которые Docker создал как настоящие каталоги в корне
файловой системы. Внутри — рабочие конфиги, и под `/home/san` они не попадают, то есть
обычный `rsync ~/` их не заберёт:

```
/path/to/config              → jellyfin /config   (в т.ч. encoding.xml)
/path/to/cache               → jellyfin /cache
/path/to/transmission/data   → transmission /config
```

Суммарно 523 МБ живых данных. Потеряете — Jellyfin забудет пользователей, библиотеки и
метаданные, Transmission — все закачки. Заодно это шанс переехать на нормальные пути и
поправить volume в compose.

### Мина 2 — жёсткие ссылки Immich ↔ Jellyfin

Домашние видео лежат одним файлом по двум путям — `~/media/home` и библиотека Immich.
Экономит 47,6 ГБ. Синхронизировать **только с флагом `-H`**, иначе приедет вдвое больше
данных и сломается автосинк. И то и другое обязано остаться **на одном томе**: на новом
сервере оба каталога bind-монтируются из `/mnt/storage` — не разносить по разным дискам.

### Мина 3 — база Immich

Postgres лежит bind-монтированием в `~/immich-app/postgres`. Копировать **только с
остановленными контейнерами** — копия живой базы приедет битой. В ней же хранится
настройка аппаратного ускорения, выставленная через API: на новом сервере `/dev/dri`
нет, поэтому VAAPI надо будет выключить отдельно, конфиг-файлом это не лечится.

### Мина 4 — `nft flush ruleset`

Никогда не выполнять на хосте — сносит правила Docker вместе со своими, сеть контейнеров
умирает.

### Мина 5 — watchtower и версия Docker API

Образ `containrrr/watchtower` собран с клиентом API 1.25, современный демон требует 1.40
и молча отвергает запросы. Обновлятор при этом падает, создавая ложное ощущение защиты.
Лечится переменной `DOCKER_API_VERSION=1.44` — проверить, что она доехала.

### Мина 6 — bind-mount привязан к inode

Docker привязывает bind-mount к inode при старте контейнера. Подмена каталога целиком
оставляет nginx смотреть в удалённый inode — так у `vpn-mirror` все подписки
превращались в 404. Файлы менять по одному, каталог не пересоздавать.

- **VAAPI пришлось гасить через API:** база приехала со старого сервера со значением `vaapi`,
  а `/dev/dri` на новой машине нет.

## 6. Порядок работ

Шаги 1–2 не требуют простоя. Простой начинается с шага 3 и длится столько, сколько идёт
копирование базы.

### Шаг 1. BIOS на новом сервере — СДЕЛАНО 14.08.2026

`Restore on AC Power Loss → Power On` выставлен, сервер поднимется сам после отключения
света. Это была единственная блокирующая задача.

**XMP сознательно не включён** — профиль работал нестабильно, память идёт на JEDEC. Для
файлового сервера потеря в пределах погрешности, всё упирается в диск и сеть. Осадок в
том, что эти же планки раньше проходили memtest 13 проходов на XMP 3200, правда в другой
плате. Когда сервер поживёт — прогнать memtest ночью, чтобы исключить подсевшую планку.

### Шаг 2. Досинхронизация данных

С 12 августа на источнике прибавилось около 28 ГБ. Флаг `-H` обязателен — см. мину 2.

```bash
rsync -aHAX --info=progress2 --delete /home/san/media/ san@192.168.101.20:/home/san/media/
```

```bash
rsync -aHAX --info=progress2 --delete /home/san/immich-app/library/ san@192.168.101.20:/home/san/immich-app/library/
```

Отдельно забрать то, что лежит вне `/home/san`:

```bash
sudo rsync -aHAX /path/to/ san@192.168.101.20:/tmp/pathto-config/
```

```bash
sudo rsync -aHAX /opt/zapret/ san@192.168.101.20:/tmp/zapret/
```

```bash
sudo rsync -aHAX /usr/local/sbin/ san@192.168.101.20:/tmp/sbin/
```

### Шаг 3. База Immich — простой

Останавливать **весь** стек Immich, а не только postgres.

```bash
cd ~/immich-app && sudo docker compose down
```

```bash
sudo rsync -aHAX /home/san/immich-app/postgres/ san@192.168.101.20:/home/san/immich-app/postgres/
```

Права владельца обязаны сохраниться — postgres не поднимется с чужим uid.

### Шаг 4. Хостовая обвязка

Разложить по местам: скрипты в `/usr/local/sbin`, юниты в `/etc/systemd/system` (кроме
`battery-guard` и `hdparm-apm`), `/opt/zapret`, конфиги nftables. Поправить в них имя
интерфейса на `enp3s0`, затем включить:

```bash
sudo systemctl enable --now home-gateway-rules vpn-routing tv-vpn vpn-guard.timer ip-defend.timer vpn-mirror.timer immich-jellyfin-sync.timer certbot-renew.timer zapret
```

Заново привязать ключ бота к forced command `zapret-ctl` в `authorized_keys` нового хоста.

### Шаг 5. Переключение адреса — точка невозврата

Старый сервер выключить (или увести на другой адрес), новому отдать `192.168.101.7`
через netplan. Проброс 80/443 на роутере переделывать не нужно — он смотрит на `.7`.
Устройства, у которых прописан шлюз `192.168.101.7`, подхватят новый сервер сами.

DNS: AdGuard слушает на `192.168.101.7:53` — до переключения клиенты сети останутся без
резолвера, поэтому окно простоя лучше делать коротким.

### Шаг 6. Запуск и добивание хвостов

Поднять стеки по очереди, начиная с `web` и `immich-app`. Затем выключить в Immich
аппаратное ускорение — оно в базе, а `/dev/dri` на новой машине нет:
`PUT /api/system-config` → `ffmpeg.accel = disabled`.

Потери производительности нет: i3-12100F даёт 4,13x на 1080p чистым процессором против
3,8x у старой связки с VAAPI.

## 7. Правки конфигов

| Где | Параметр | Что сделать |
|---|---|---|
| `.env` бота | `DISK_PATHS` | был один диск — добавить `/mnt/storage` |
| `.env` бота | `SMART_DEVICES` | `/dev/sda` → NVMe + Seagate |
| `.env` бота | `BATTERY_CHARGE_LIMIT` | `0` — батареи нет |
| `.env` бота | `POWER_CHECK_INTERVAL_SECONDS` | `0` — детектор света мёртв без батареи |
| `.env` бота | `MEDIA_PATH` | оставить `/home/san/media` — путь сохраняется через bind |
| `docker-compose.override.yml` | devices | SMART: `/dev/sda` → новые диски |
| `~/jellyfin`, `~/immich-app` override | `/dev/dri` | проброс убран — проверить, что не вернулся |
| Jellyfin `encoding.xml` | `HardwareAccelerationType` | `none` |
| netplan | интерфейс | `enx00e04c…` → `enp3s0` |
| zapret config | `IFACE_LAN` / `IFACE_WAN` | переписать под `enp3s0` |
| `/etc/fstab` | `/mnt/storage` | bind-монтирование `immich-app` и `media` в `/home/san` |

**Почему пути обязаны совпасть.** На `/home/san/immich-app` и `/home/san/media`
ссылаются compose-файлы, `.env` бота и `UPLOAD_LOCATION` Immich. Поэтому данные
физически лежат на `/mnt/storage`, а в привычные места приходят bind-монтированием —
тогда ничего в конфигах трогать не нужно.

При переезде VPN-сервера переносить **оба** файла — `/root/mieru-server.json` и

у всех восьмерых. Зеркало тянет конфиги с VPS по SSH и при его недоступности не трогает
старую копию, поэтому `VPN_MIRROR_HOST` переключать **до** смерти старого сервера.

## 11. Медиапул из старых дисков

Собран 14.08.2026. `/mnt/pool` — mergerfs на 915 ГБ:

| Ветка | Диск | Наработка | Состояние | Режим |
|---|---|---|---|---|
| `/mnt/disk1` | WD5000LPVX | 4 414 ч | ноль ошибок | **RW** |
| `/mnt/disk2` | ST500DM002 | 77 835 ч | 8 нечитаемых секторов | **RO** |

Больной диск подключён только на чтение — новые файлы на него не попадают, а старые читаются,
пока читаются. Файл целиком лежит на одном диске, поэтому смерть диска уносит только его фильмы.

В пул уходят **только** `movie`, `show`, `music` — через bind в `/home/san/media`, чтобы пути в
compose и `.env` не менялись. `home` и `books` остаются на `/mnt/storage` рядом с библиотекой
Immich: их связывают жёсткие ссылки, а те работают лишь в пределах одного тома.

**Защита от залипаний.** Битый сектор заставляет диск переповторять чтение, а ядро по умолчанию
ждёт 30 секунд — на это время замирает и воспроизведение, и листинг каталогов пула. Поэтому
таймаут снижен до 7 секунд и включён SCT ERC (`scterc,70,70`), чтобы диск сдавался сам.
Восстанавливается после перезагрузки через `/etc/udev/rules.d/99-disk-timeout.rules`.

Диск из ноутбука планируется добавить третьей веткой примерно через неделю — разметить и
смонтировать как `/mnt/disk3`, затем дописать ветку в строку mergerfs в `fstab`.
